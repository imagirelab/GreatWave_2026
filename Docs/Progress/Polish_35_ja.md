## 0. 結論

1. **RTX3060 は借りていないので、代理測定（RTX 3080）で測り直した。** 設計35 の `DS35Perf.exe` は設計34 の古い場面（爪 148 本・飛沫 186 個・DS27 の材質）を描くので、今の体験の場面を測れない。仕上げ33修正01 の体験の場面を `Polish35/Scenes/PL35_Release.unity` へ写し、負荷の計測器 `PL35PerfProbe`（起動引数 `--pl35perf` の時だけ働く）を置いて、入口 → 導入 → 接近 → 形成を体験のまま進め、大波の時刻 t 11〜12 s（最大密度の区間）を繰り返して測った。PL29/PL30 の材質、仕上げ33修正01 の爪（104,707 頂点・199,880 三角形）、飛沫（時計の飛沫の段の 3 つの粒の組：仕上げ31 の 2,500 粒＝白・生成り 2,372 粒＋灰の白 128 粒と、設計39 の小飛沫 317 粒）がすべて入っている（作る部の記録は「2 つの粒の組 2,372 粒・317 粒」と書いたが、計測器が数を書き出すのは初めの 2 つだけだった。評審の後に場面から数え直して直した）。あわせて、体験の通し（設計50 の自動の試し）の形成の全区間を、前（仕上げ33修正01 の exe）と後（仕上げ35 の exe）で交互に 2 回ずつ測った。
2. **81・112・199 は代理で不合格（記録。本判定は RTX3060・PS VR2 で保留）。**
   - 最大密度の区間（後、2 回）：1920×1080 の原画視点 29.6・30.1 fps、座席 v1 29.6・29.0 fps、体験の画面 29.7・29.3 fps。間隔 p95 は 34.4〜44.1 ms で、95% ≤ 33.3 ms を満たさない。
   - 形成の全区間（後、2 回）：平均 29.0・28.7 fps、間隔 p95 45.5・45.4 ms、33.3 ms を超えるフレーム 58・60%。
   - **律速は CPU の主スレッドで、そのうち毎コマ 29.4〜30.2 ms が船用水面データの作り直し（`DS43BoatWater`）。** 座席の船の段（`seat_boat`）の水の問い合わせが、大波の τ が変わるたびに索引を作り直す。これは設計43 の限界 11・段階9確認 F9-4 で、計画 §5.2 では仕上げ43 の項目（「船用水面データの作り直しの置き換え」0.75 日）なので、この群では直していない（後の群の作業を差し込まない。§5.1）。作り直しを止めると、同じ区間が 1920×1080 で約 320 fps（間隔 p95 3.7〜3.9 ms）、立体の代理で約 300 fps（4.1〜4.2 ms）になる。
   - **爪の寄与（評審 2 の指摘で直した）**：作り直し（CPU 主 約 33.2 ms の約 88%）の上に爪の段（2.6〜3.1 ms）が加わって 33.3 ms を越える。爪を全部切ると、平均は 6 回とも 31.3〜33.0 fps で 30 fps を越え、間隔 p95 は 3 回が 31.2〜32.1 ms（33.3 ms 以下）、3 回が 40.5〜41.8 ms。つまり 30 fps の線の上では爪も効いている。ただし作り直しを止めれば爪ありで 289〜329 fps になるので、直すべきは作り直し（仕上げ43）で、見え方を変えて爪を減らす理由にはならない。
   - 設計50 の exe（仕上げの前、9/30 の状態）を同じ日に 1 回動かすと、形成の全区間は 38.4 fps・間隔 p95 34.4 ms・CPU 主 p50 24.8 ms。今は 29 fps・45.5 ms・35.4 ms で、仕上げ28〜33 の間に CPU 主スレッドが約 10.6 ms 増えた（大波の時刻 0〜1 s の爪のない所で +6.6 ms、7〜10 s で +11 ms。船用水面データの作り直しの増え（主役波・海のシートの作り直し）と爪の段の約 2〜3 ms とみる。切り分けはしていない）。
3. **GPU は予算の内。** 時刻を止めた立体の代理（2064×2208×2、4×MSAA）の GPU p95 は 2.15 ms（8.9 ms の内）。切り分け：主役波 0.62 ms、周りの海 0.32 ms、爪 0.08 ms、飛沫 0.01 ms（仕上げ30・31 の引き継ぎの答え）。作り直しを止めて動かしたときは 3.2〜3.3 ms。ただし CPU 律速のまま測ると FrameTiming の GPU p95 は 12.8〜13.6 ms になる（CPU の待ちを含むとみる。記録）。

## 2. 測り方

### 2.1 計測器 `PL35PerfProbe`（`Unity/Assets/GreatWave/Polish35/Scripts/PL35PerfProbe.cs`）

- 体験の Release の場面の写し `PL35_Release.unity` に置く。起動引数 `--pl35perf` が無ければ何もしない（体験の exe と同じ exe）。
- 入口の画面で `DS50Shell` の Begin（利用者の Enter と同じ道）を呼び、導入（操作なし。introMaxS 45 s で引き継ぐ）→ 接近 → 形成を体験のまま進める（約 55 s）。大波の時刻が 10.8 s を過ぎたら共通時計（`GWClock`、Master）を止め、毎フレーム `clock.Seek(形成の始まり + t)` で t を [11, 12) の中で実時間の速さで繰り返す（設計35 の `DS35PerfRunner` と同じ区間と進め方）。段（流れ・水面・座席の船・船用水面データ・白・爪・飛沫・出来事・音）は体験と同じ関数を同じ順で呼ぶ。

## 12. 決定の記録（Q24：推奨の案を選び、理由と落とした案を残す。進行役の決定ではなく作る部の選び。評審で変えられる）
