# 制作手順と引継ぎ

更新日：2026-09-25

## 指示と担当

利用者は「番号ごとにコミット」「完成点で確認」「完成点ごとに静止画・動画を保存」「旧試作を参照せず新たに検証」「進行役は指示・確認、実装を別担当へ委任」を指定した。Opusの代わりにGPT-6を実装担当とすることは利用者の確認済み。現在HMDは手元にない。

| 担当 | 作業 |
| --- | --- |
| 進行役 | 指示、差分・実画像・実測のレビュー、利用者への報告と確認 |
| 実装担当GPT-6 | コード・設定・素材・文書の制作、実行、証拠保存、番号ごとのコミット、修正 |
| 利用者 | 完成点の報告を確認し、方針・機器条件を指定する。各番号の継続には毎回の返答を要求しない |

## 各番号の手順

1. 公式資料と今回の検証結果から、確かめる一点を決める。
2. 実装担当が新しい成果物を作り、可能な試験を実行する。
3. `Docs/Progress/Step_XX_ja.md` に条件、結果、保留事項、再現方法を残す。
4. 一番号を独立した日本語コミットにする。修正も番号を示す。
5. 進行役が成果と証拠をレビューする。コミットの存在だけで合格としない。

旧試作や履歴内の制作物は参照しない。Git履歴は保存する。ソフトの存在確認と実際の書き出し成功を区別する。

## 証拠と確認条件

実画像・動画を `Docs/Evidence/M0/` などへ保存し、番号、シーン、時刻、視点、ビルド条件、入力操作、確認範囲を記録する。Unityの実出力を使い、モック画像を証拠としない。自動カメラで記録した場合はその事実を表示し、HMD追跡とは区別する。PC画像・動画からHMD性能を推測しない。公開記録には認証情報・個人識別情報を入れない。

最新指示（2026-09-25）により、代理が各番号の証拠を独立レビューして継続する。完成点M0〜M4でも報告・保留一覧を残す。HMDなど未所持の機器を要する合格条件を解除したわけではなく、独立した作業だけを先行する。
