## 焼きの形（Unity が読む形。`u_bakeio.py` の頭にも同じ説明）

- `meta.json`：平らな配列だけ（Unity の JsonUtility で読む）。`schema` = `GreatWave.RT48.bake/1`、`x_origin_m`（527.0）、`n_points`（8,192）、`fps`（24）、`frame_first`・`frame_count`・`pair_count`、`k_frame`、組ごとの `pair_interp`（1 補間する）・`pair_reason`（0 補間、1 K から先、2 C4 で外れた、3 自分と交わる、4 その他）・`pair_lm_crest`・`pair_lm_lip`、コマごとの `crest_x_m`、`x_range_m`、`taper_m`（100・200・825・925 m）、`onset_s`・`contact_s` など、座席の表 `seat_x_m`・`seat_end_s`、閉じた線の索引（`loop_frame_first`・`loop_frame_count`・`loop_kind`・`loop_point_first`・`loop_point_count`）、ファイルの大きさと SHA-256。
- `pairs.bin`：float32 リトルエンディアン [組][A, B][点][x, y]。x は 527.0 m からの距離、y は静かな水面から。
- `loops.bin`：float32 リトルエンディアン [点][x, y]（閉じる点は重ねない）。`loop_kind` 0 離れた水、1 囲まれた空気。

### 気づいたこと（直していない）

- **粗い元はクリップのほとんどが 24 コマ/秒になる。** manifest では補間する組が 570 のうち 38 だけ（理由：C4 で外れた組 387、K から先 145）【測った：data/coarse/manifest.json の pairs の reason】。Unity は焼きのとおりに補間しない組で前のコマを保つ。計画の字 6「ここから 24 コマ/秒、補間なし」は K から出す決まりなので、K の前の C4 で外れた組では画面に字 6 が出ない（デスクトップと動画では状態の行に「補間なし・C4 で外れた組」と出るが、VR には出ない）。字の決まりを変えるかは計画の外なので、上へ伝える。
- DS50Shell の `[RuntimeInitializeOnLoadMethod]`（`StreamingAssets/gwdata` があれば作業ディレクトリを移す）と GWClock の同じ仕組みが、同じ Assembly-CSharp にあるので RT48 のプレイヤーでも走る（ログに `DS50_DATA_ROOT … used=False`）。RT48 のプレイヤーに `StreamingAssets/gwdata` はないので何もしない。RT48 に StreamingAssets を足す時は気をつける。
- OpenXR のプラグインは `-rt48xr` なしでも起動の時に runtime を探し、SteamVR がない時はログに `XR_ERROR_RUNTIME_UNAVAILABLE` を出す（その後は普通に動く）。
- Mock で XR が動いた時、`XRSettings.stereoRenderingMode` は MultiPass、目のテクスチャは 0×0 と出た（その瞬間の値。OpenXR の報告は SinglePassInstanced）【測った：p6_mock2.log】。左右の眼の絵が single-pass instanced で描けているかは手順 5 で確かめる。
- Unity と manifest のコマごとの船の差（T11c、縦揺れ 0.011°）は C6 の幅（0.01°）に近い。C6 は「Python で同じ曲線から求めた値」との比べなので、手順 5 では Python も焼いた 8,192 点の線から求める（`u_bakeio.boat_at` がその形）。
