# Alembic 入出力の小規模検証

Steam 版 Houdini Indie 22.0.429 で、正弦関数による変形メッシュを 3 フレーム書き出し、Alembic SOP で再読込して元の頂点座標と照合した。

**これは FLIP 流体シミュレーションではない。Unity の再生、HMD の動作・性能、流体物理の精度は未検証。** この検証で確認した範囲は、既存の Indie ライセンスによる Alembic の書き出しと Houdini 内での再読込である。

## 収録ファイル

| ファイル | 内容 |
| --- | --- |
| [正弦波面_入出力検証.hiplc](正弦波面_入出力検証.hiplc) | 格子、正弦変形、出力、再読込を含む小型の制作元シーン |
| [正弦波面_3フレーム.abc](正弦波面_3フレーム.abc) | 実際に書き出した 3 フレームのメッシュ |
| [検証結果.json](検証結果.json) | フレーム別の点数・面数・座標誤差・頂点変位 |
| [検証スクリプト.py](検証スクリプト.py) | 別の保存先に検証シーンと Alembic を再生成するスクリプト |

制作元シーンと Alembic は完了済みの検証からそのままコピーした。収録時に再計算・再書き出しは行っていない。スクリプトには出力先指定と相対パスによる記録を追加し、構文を確認した。この整理後のスクリプトによる再生成は未実行である。

## 確認済みの結果

- 24 FPS、フレーム 1・2・3。
- 各フレームは 81 点、64 面。
- 再読込した頂点と制作元の最大座標誤差は、各フレームとも 0 m。
- 隣接フレームの最大頂点変位は約 0.04728 m。静止メッシュではなく、時間変化するデータが収録されている。
- Alembic は 6,436 バイト、制作元シーンは 81,273 バイト。

数値の詳細は [検証結果.json](検証結果.json) を参照する。書出しと読込のノード種別はいずれも `alembic`。実際の実行時には Steam クライアントが起動しており、`hou.licenseCategory()` は `Indie` を返した。

## 移動と閲覧

このフォルダー内の制作元シーンと Alembic を一緒に保持する。シーン内の Alembic 書出先・読込先は `$HIP/正弦波面_3フレーム.abc` であり、特定のドライブやユーザー名を必要としない。JSON 内のファイル名も、このフォルダーからの相対パスである。

コピー先の制作元シーンを手動更新モードで読み込み、両ノードの参照がコピー先の Alembic に解決されることを確認した。元のバイト列を保持したため、HIP の保存時環境記録と Alembic の自動生成された由来メタデータには旧保存先の絶対パスが残る。これらは今回のノードの実行に必要な外部ファイル参照ではなく、読み込み時の `$HIP` は現在のシーンの位置に更新される。

Houdini が日本語のノード識別子を拒否したため、内部識別子には ASCII を使い、表示コメントと説明文を日本語にした。

## 再現手順

1. 利用可能なライセンスを持つ Houdini のコマンドライン環境を開く。Steam 版を使う場合は Steam を起動しておく。本検証では Steam 版 22.0.429 を使用した。
2. リポジトリのルートを作業ディレクトリにして、次を実行する。

```text
hython "Houdini/tests/interop_probe/検証スクリプト.py" --output-dir "Houdini/results/interop_probe_reproduction"
```

3. 指定した保存先の `検証結果.json` と生成された制作元シーン・Alembic を確認する。

`--output-dir` を省略すると、このリポジトリ内の `Houdini/results/interop_probe_reproduction` に出力する。既存の制作元シーンや Alembic がある場合は停止するため、再実行時は別の新しい保存先を指定する。元の旧 FLIP シーンは読み込まず、シミュレーションキャッシュも生成しない。

## 残っている確認

- 旧 FLIP シーンの読み込み時警告の原因と、シミュレーションの再現性。
- 物理条件を設定した小規模 FLIP シミュレーションと、その結果の Alembic 書き出し。
- Unity への読み込み、対象プラットフォームでの再生、描画負荷とメモリ使用量。
- HMD と船の操作を含む作品としての動作。
