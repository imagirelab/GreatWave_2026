# 有限水深の集束波群：総振幅 0.6 m の試行

**実際の FLIP 計算と Alembic 出力は完了したが、参照の大波の形には未到達。** Blender の側面・斜視で第 12・24・36・48 フレームを確認すると、第 24 フレーム付近に急な前縁と短い突出があるが、その後は低く広がり、参照模型のような深い C 字の開口は見られなかった。幅方向にも緩い曲がりはあるが、広い横長の波冠である。中央断面を含む詳しい判定と動画は [制作側の試行記録](../../Blender/great_wave/docs/milestones/2026-09-24_focused_packet.md) を参照する。

この試行は平らな底で波群の集中を調べる。参照 OBJ は評価のために使い、毎フレームの位置拘束や速度の再注入は行わない。白波を追加して形態上の未達を隠さない。追加の振幅条件や高解像度計算は実施していない。

## 初期化した場

各成分 j について、水深 h、方向の単位ベクトル d、水平位置 r=(x,z) とする。

```text
ω_j² = g k_j tanh(k_j h)
φ_j = k_j d_j · (r − r_f) − ω_j (t − t_f)
η = Σ a_j cos φ_j
u_XZ = Σ a_j ω_j cosh(k_j y) / sinh(k_j h) cos φ_j d_j
v_Y = Σ a_j ω_j sinh(k_j y) / sinh(k_j h) sin φ_j
```

底は y=0。t=0 の水面と速度を同じ成分から作り、粒子の初期位置・初期速度に一度だけ使う。その後は Houdini の圧力投影・重力・移流によって進む。[有限水深の線形分散関係](https://web.mit.edu/fluids-modules/www/potential_flows/LecturesHTML/lec19bu/node4.html) に基づく初期化であり、FLIP の実結果を線形波として再描画する処理ではない。

## 線形設計と実水面の時間発展

解析式の数値確認では、発散と静水面 y=h での線形運動学条件の残差は約 10⁻¹⁶ だった。以下の残差に使う η_t は線形設計の時間微分であり、FLIP の水面変化から測った値ではない。

- t=0 の解析水面増分は −0.5831～+0.5677 m。最大値は名義の集中振幅 0.6 m の約 94.6% で、開始時から既に大きい波がある。
- 上昇した解析水面 y=h+η で、`v_Y − η_t − u_X η_x − u_Z η_z` の最大絶対値は **2.0683 m/s**。線形設計の時間発展を実水面へそのまま適用すると、非線形運動学条件を満たさない。この値は FLIP の初期状態や後続の時間発展が運動学条件に違反した証拠ではない。
- その初期解析水面での最大速度は 3.8854 m/s。線形設計からの調整が FLIP の結果へ与える影響は、今回の計測では分離していない。
- 閉じた側面・端面での法線速度条件は、この成分和だけでは満たしていない。壁近傍の高水位フラグが出ないことだけでは、反射がないと証明できない。

したがって、これは「線形設計の初期場を非線形の FLIP で発展させた試行」であり、「大振幅で自己整合した実海波の再現」や「指定時刻での集束成功」とは記載しない。数値表は [初期場の確認](初期場の確認.json)。この確認は通常の NumPy で再実行でき、Houdini のシミュレーションを起動しない。

## 出力と確認済みの範囲

計算・粒子・体積場の保存時間は合計 24.426 秒、表面化・保存は 70.540 秒。1 フレーム合計は 0.438～1.685 秒。各フレームで採取した最大メモリは 1429.93 MiB。連続監視の真のピークではない。

最高粒子は第 10 フレームの Y=2.2137 m、位置 X≈−2.532、Z≈−0.060。名義の集中時刻である第 37 フレームではなかった。最大粒子速度は全期間で 8.3122 m/s。いずれも単独の極値で、形態の合格や物理的収束の指標にはしない。

表面 Alembic は **61,200,700 バイト**。Houdini に再読込した第 1・24・48・72 フレームは元の表面キャッシュと頂点数が一致し、座標誤差は 0。粒子数が一定でも表面体積保存を意味しない。解像度収束、厳密な体積保存、Unity と HMD は未検証。

大きい結果は Git 対象外の `../results/focused_packet/試行01/` にある。

## 再現

有効な Houdini Indie の `hython` を使用する。計算スクリプトのメモリ採取は Windows API を使うため、現状の再現手順は Windows 専用。このディレクトリから、未使用の出力先を指定する。

```powershell
hython "集束波群を計算.py" --frames 6 --output-dir "../results/focused_packet/再現_6フレーム"
hython "集束波群を計算.py" --frames 72 --output-dir "../results/focused_packet/再現_72フレーム"
hython "表面を書き出す.py" --cache-dir "../results/focused_packet/再現_72フレーム"
```

6 フレームの確認後に 72 フレームへ進む。出力の既存計測・Alembic は上書きしない。ソース `集束波群.hiplc` は再生成するため、手作業による変更があれば先に別名で保存する。個人の絶対パスを実行条件にしない。最大 20 万粒子、採取メモリ 12000 MiB、計算ループ 20 分の上限を持つ。

## 次に比較可能な仮説：まだ実行しない

1. **初期時刻と位相・周波数幅。** 現在は開始時に既に名義振幅の 94.6% に達する。解析場だけで、早く開始する場合や周波数幅を広げる場合の初期最大振幅と、線形 η_t を使った実水面上の残差を先に比べる。その残差が減る一条件だけを FLIP と比較し、実際の形態が改善するか確認する。開始時刻を早めれば必要な総フレーム数も増えるので、72 フレームのまま集中前に打ち切らない。
2. **方向分布。** ±15° と ±25° を同じ総振幅・位相・深さで比較し、中央と肩の高さ差を測る。波冠が局所化しても、鉛直の噴流になる可能性がある。前へ伸びる水舌とは区別する。[三次元砕波の研究](https://www.nature.com/articles/s41586-024-07886-z) も機構を分けている。
3. **相対水深。** 水深 1.4→2.4 m で波数・総振幅・粒子間隔を固定し、底面の影響と深さ方向の速度差が巻き形状へ与える影響を比べる。粒子数は概算 19 万程度になるため実数で上限を確認する。解像度を上げる試験ではない。
4. **参照に基づく初期水体。** 巻き上がる前の閉じた水体と一度だけ与える速度を使い、圧力投影後に自然に前へ伸びるかを検証する。最終の C 字模型を最初から置けば、その後の落下は示せても、そこへ形成する過程を示したことにはならない。

一度に複数の仮説を変更せず、いずれも未検証の提案として扱う。現在の未達を白波や着色で補って合格とはしない。
