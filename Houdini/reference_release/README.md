# 参照の水体を初期値にした自由発展

参照模型の巻いた水体を初期状態として与え、その後を実際の FLIP で計算する試行。**初期値に既にある巻き形状が自然に形成されたことは、この試行では示せない。** 落下、前進、接水、崩壊を評価する。

入力の体積化、6 フレームの数値確認、96 フレームの自由発展、Alembic の再読込まで完了した。実際の表示では第 1 フレームの C 字と厚い唇は読み取れるが、第 12 フレームで開口は見えにくくなり、第 24 フレームでは低く広がる。**現在は参照初期値の崩壊を調べる診断試験であり、作品の大波としては未到達。**

## 入力と水槽

- `inputs/参照水体.obj`：変換を適用済みの閉じた水体。X は前、Y は上、Z は幅方向、単位 m。入力には水面下の基座も含まれる。
- `inputs/確認点.json`：開口内の空気点と、唇・幹の水体内点。`points` の各要素に `name`、`kind` (`air` / `water`)、`position` を持たせる。
- 基準の静水位は Y=1.4 m、参照水体の水面上の高さは 3 m。槽は長さ 24 m、幅 8 m、高さ 6 m。
- 参照 SDF を、下面が Y=1.1 m の十分大きい上側領域と SDF Intersection で切り取りする。模型内では `phi=max(phi,1.1−Y)` と等価な操作であり、非活動の内部ブロックも含めて処理する。その後に静水体 SDF と Union で結合する。接合の重なりは水面下に置き、開口の空気を水で埋めない。

[VDB From Polygons](https://www.sidefx.com/ja/docs/houdini/nodes/sop/vdbfrompolygons.html) で符号付き距離場を作り、内部を負、外部を正として確認する。体積化のボクセルは 0.05 m、粒子間隔は 0.12 m、FLIP の格子間隔は 0.24 m。模型の薄い唇や開口が数値的に保たれるか、SDF と粒子表面の両方を確認する。

SDF の外側の帯幅は 3 ボクセルであるため、記録値の +0.15 m は遠方で切り詰められた値を含む。これを正確な表面距離とは扱わない。確認点の符号と実際の形状表示を併用する。

採用した入力の SHA256 は `958320e4df727a5eef51f1eb52af8b12209533b92ae3aca1da323d1157faf963`。ポリゴンの水面下に複数の輪郭を直接ふさぐ方法では逆向きの重なりが見つかったため、最終入力は切り取り前の閉体積へ戻し、上記の体積切り取りを採用した。旧準備と新準備の粒子表面 OBJ は同一の SHA256 となり、水槽と結合後の水面は変わっていない。

[初期断面の比較](previews/初期断面.png) では、粒子表面の開口は参照より 22～31% 狭く、同じ測線の唇の鉛直厚さは 21～41% 増した。細い爪も失われている。この比較だけでは SDF、結合、粒子化、表面再構成のどの段階が各差を生んだかを切り分けられない。元の参照と閉体積の同じ測線の差は 1 mm 未満だった。[形状検証の数値](初期形状検証.json)

## 得られた計算と制限

- 全 96 フレームで 162,492 粒子、ID の新生・消失は 0。粒子の非有限値は検出されなかった。
- 物理計算と粒子・体積場の保存は合計 43.54 秒、表面化と保存は 122.05 秒。フレーム合計は 1.460～2.406 秒、最大採取メモリは 2071.13 MiB。連続監視の真の最大値ではない。
- `../results/reference_release/本計算01/FLIP参照水体_96フレーム.abc` は 77,400,894 バイト。第 1・24・48・96 フレームを再読込し、頂点数と全座標が元の表面に一致した。
- 初期の厚い唇 32 粒子と、初期に静水位以下だった池水 158,400 粒子の中心間距離は、第 14 フレームで初めて 0.24 m 以下、第 18 フレームで 0.12 m 以下となった。これは接水の候補区間であり、全水面の最初の接触を確定しない。別の唇部分が先に接水する可能性がある。
- `|Z|>3.6 m` かつ `Y>1.55 m` の側壁接近フラグは第 17 フレーム、下流壁は第 61、上流壁は第 77 フレームから出る。これは反射開始の正確な時刻ではないが、4 秒全体を無限海面の自由伝播とは扱えない。
- 初期の上流域 `X<−6 m` の高さ P99.5 は第 1～6 フレームで約 0.000149 m 低下し、第 6 フレームの鉛直速度中央値は約 +0.0000875 m/s。背景水全体が弾道落下している状態ではなかった。

## 表面の再構成だけを変えた比較

第 1・6・12 フレームの同じ粒子を使い、Particle Fluid Surface の `Droplet Scale` (`surfacedistance`) だけを 1.0→0.8→0.6 と変えて 9 個の模型を出力した。粒子の位置・速度・`pscale` は変更せず、主 FLIP の再計算はしていない。実際の `pscale` は全て約 0.144 m。Influence Scale=3、Min Radius in Voxels=1.5、Voxel Scale=0.75、Union Compressed Fluid Surface は有効のまま保持した。

1.0 の各基準表面は元キャッシュと全頂点が一致する。9 個の模型はいずれも一つの頂点接続成分で、境界辺・三面以上が共有する辺・向きが不整合な共有辺・面積がほぼ零の面は検出されなかった。自己交差は未検証。第 1 フレームの表示表面が囲む体積の絶対値は 309.53→291.53→263.83 m³ と変わるが、これを実際の流体の質量・水量の変化とは扱わない。開口・唇の厚さと、動的な崩壊が改善するかは同じ断面で比較する。小さい値を自動的に採用しない。

[比較の数値と設定](表面感度.json)、[再現スクリプト](表面感度を確認.py)。模型は Git 対象外の `../results/reference_release/表面感度/` にある。

## 表面再構成の感度

表示表面については、同じ粒子のまま Droplet Scale 1.0・0.8・0.6 を比較した。小さい値は初期開口の縮小を減らすが、第 12 フレームの C 字はいずれも戻らない。[表面感度の判定](表面感度.md) と [図](previews/表面感度.png) を参照。掲載動画は 1.0 条件で、感度試験のために主 FLIP を再計算していない。

## 初期速度

水面からの高さを使い、次の速度を一度だけ初期粒子に与える。

```text
q = clamp((Y − 1.4) / 2.5, 0, 1)
w = q² (3 − 2q)
vX = 2.8 w m/s
vY = −0.3 w² m/s
vZ = 0
```

これは上層の前進と小さい下降を指定する制御された初期値であり、実海の測定速度や特定の波の厳密解ではない。静水位より下の初期速度は 0。初期形状と速度を一度与えた後は、重力 9.80665 m/s² と FLIP の圧力投影・移流に従う。毎フレームの目標位置、追加の粒子、参照形状を追う外力は入れない。[FLIP の速度投影](https://www.sidefx.com/docs/houdini/fluid/liquids.html) を使うが、設定した初期値の物理的妥当性や数値収束をそれだけで保証するものではない。

## 実行の順序

Windows の有効な Houdini Indie `hython` を使用する。メモリ採取が Windows API を使うため、現状の実行コードは Windows 専用。

```powershell
hython "参照水体を計算.py" --frames 1 --output-dir "../results/reference_release/準備01"
hython "参照水体を計算.py" --frames 6 --output-dir "../results/reference_release/試行01"
hython "参照水体を計算.py" --frames 96 --output-dir "../results/reference_release/本計算01"
hython "表面を書き出す.py" --cache-dir "../results/reference_release/本計算01"
```

1. SDF の空気点・水体点を確認し、`初期SDF_表面.obj` を実際に見る。
2. 第 1 フレームの粒子表面でも同じ点を確認し、`初期粒子_表面.obj` で開口と厚みを見る。
3. 6 フレームで圧力場が更新されること、粒子数・有限性・境界・メモリを確認する。
4. 今回は 96 フレーム、24 fps、約 4 秒へ進む。コード上の絶対上限は 144 フレーム。上限は 20 万粒子、採取メモリ 12000 MiB、計算ループ 30 分。既存結果の計測と Alembic は上書きしない。
5. 表面 Alembic を保存して再読込し、元の表面キャッシュと照合する。

`参照水体の自由発展.hiplc` は再生成される。手作業で編集する場合は先に別名で保存する。出力は Git 対象外の `../results/reference_release/` に置く。粒子数×間隔³は数量からの代理量であり、厳密な体積保存の測定ではない。第 1 フレームの DOP 場は未更新の場合があるため、後続の白波処理用の体積場は第 2 フレーム以降を確認する。

## 短時間の誘導から解放する案：FLIP への適用は未実施

別途 [解析的な誘導場](guiding_field.py) とその設定を実装し、NumPy による数値確認を行った。B 条件として FLIP に適用する計算は未実施。詳細は [制御と自由発展](制御と自由発展.md) を参照する。現在の A 条件は高さに応じた非零の初期速度を持ち、初期速度が全て 0 の A0 条件はまだ計算していない。以下は誘導を適用する際の確認事項であり、A の実行内容ではない。

形成の制御を調べる場合は、この初期値試験とは別に次の手順が必要になる。

1. 巻き上がる前からの水体と速度の目標を物理時間ごとに用意し、目標が与える体積・時間・移動速度を確認する。
2. 力を作用させる場所を水面の近傍へ限定し、加速度の単位と上限を定める。速度を直接毎フレーム上書きせず、力を `force = mass × acceleration` として扱う。
3. [FLIP Solver の Particle Velocity 入力](https://www.sidefx.com/docs/houdini/nodes/dop/flipsolver) を使い、指定した期間だけ力を加える。時間窓で滑らかに弱め、解放時刻以降は厳密に 0 とする。
4. 加えた力の時間積分、仕事、最大速度、粒子数・体積指標を記録する。同じ初期値の無誘導条件と比較する。
5. 解放時の位置と速度を保ち、その後の FLIP を自由に進める。誘導中の形、解放直後、接水後を分けて評価する。

この方法でも誘導期間は外力で演出した流体である。参照 SDF の勾配に任意の大きな係数を掛け続けるだけで、自然な波の形成を証明したとは扱わない。
