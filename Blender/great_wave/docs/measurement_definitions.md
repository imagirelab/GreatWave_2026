**2026-09-20 加固（第 3.9–3.11 节、§1／§2／§3.2／§3.3／§3.4 里标「加固」的条目）**：针对 `results/step1_prepare/verify_tests/` 的审查结果，测量层现在把以前「悄悄处理掉」的东西全部数出来报告（非有限顶点、被丢掉的分量、模型自己的谷水位、改过的测量参数），并补了几组**只报告、不判定**的量（不会相互抵消的形状描述量、带符号的 S7、S8 的盲点）。判定用的定义（S1–S8 的判定值）一项都没有改。记录：`docs/records/step1_harden_measure.md`。

单位：位置用 H 归一化坐标 (X_H, Z_H)（波頂 = (0, 1)，谷的水面 Z = 0，+X = 船の側）；长度差用「画面高的 ％」（1％ = 25.94 px = 0.0151515 H，水平方向的差也用它）；角度用度，方向角 = atan2(dZ, dX)（0° = +X，向上为正）。

流水线（与建模方法无关，只看求值后的网格）：

```
Blender 对象（任意方法：Shape Key / Geometry Nodes / Alembic …）
  └─ silhouette.silhouette_mask()      求值网格 → 世界坐标三角形 → 沿 +Y 正交投影到 XZ 平面 → 遮罩

            └─ profile_metrics.measure_profile() / s7_deviation() / position_checks() / measure_sequence()
```

## 1. 轮廓遮罩（`CAM_print` 视点）

| 项目 | 定义 |
|---|---|
| 投影 | `CAM_print` 是沿 +Y 看的正交相机，所以遮罩 = 全部三角形投影到 XZ 平面后的并集（any coverage）。取景矩形用 `ViewRect` 表示，默认就是 `gw.frame` 的 `CAM_print` 取景（H 可指定，分辨率可乘系数 `scale`）；也可以用 `ViewRect.from_bounds()` 给任意矩形（Houdini 参考的大小和位置不同，就用自己的矩形；`mirror_x=True` 用于向 −X 行进的参考）。 |
| 覆盖规则 | 像素**中心**落在某个三角形内部或边上（闭三角形）即为覆盖。共享边因此不会漏缝；同一条边总是从 y 较小的端点插值，两个相邻三角形得到逐位相同的交点，结果与三角形顺序、绕向、分块无关（自测逐像素对照暴力边函数实现：差 0 px）。 |
| 实现 | 向量化扫描线：每个三角形按它跨过的像素行展开成区间，累加到差分图再做一次 cumsum。开销 ∝ 区间总数（≈ 三角形高度之和），与包围盒面积无关。退化／正侧面（投影面积为 0）的三角形不覆盖任何像素中心，直接跳过、不报警告；`thin='line'` 时另外把「比 `thin_px` 还薄」的三角形沿最长边画成 1 px 的线（会让轮廓外扩约 0.5 px，所以默认关闭，只用于诊断）。 |
| 水体（water slab） | `water_z`（默认 0 = 静水面）以下、取景范围以内全部填实。浪的网格是开口的薄片，裾落在静水面上，水面以下的浪体必须算作实心。**后果：低于静水面的谷在遮罩里看不到（显示为 Z = water_z 的水平线）。**（解释・待确认；说明书 §7d 的默认值是谷与静水面高度差 0。） |
| 非有限顶点（加固） | 求值后的网格里只要有一个顶点的世界坐标含 NaN／inf（例如某个 Shape Key 里出现 0/0），用到它的三角形无法投影，会被**去掉**。以前是光栅化器默默跳过；现在在 `mesh_world_triangles`（取网格时，先于 `y_range` 过滤）和 `mask_from_triangles`（纯 numpy 路径）里显式去掉并计数：`info['n_nonfinite_vertices']`（坏顶点数）、`info['n_dropped_triangles']`（因此被去掉的三角形数）、`info['nonfinite_vertex_indices']`（前 20 个下标）；`silhouette_mask`／`profile_of_objects` 返回的 `info` 顶层也有这两个数（各对象的分项在 `info['mesh']['objects']`），`profiles_over_frames` 每帧都带。**实测：扫掠网格中间一行去掉一个顶点（6 个三角形），遮罩 0 px 变化、全部指标逐位相同——所以只看指标发现不了，调用方必须看这两个计数。** 光栅化器自己的 `info['n_nonfinite']`（像素坐标非有限的三角形）保留作第二道网。 |
| 亚像素精度（`exact=True`，默认） | 光栅化时同时记录「轮廓边界与穿过像素中心的网格线的精确交点」（行方向一遍、列方向一遍，float32）。提取轮廓线时，每一个像素缝都换成这个精确交点，所以轮廓点是浮点精度，**精度基本不随分辨率下降**（见 §7）。代价：光栅化时间约 2 倍，外加 4 张 float32 图的内存。`exact=False` 时只有遮罩，轮廓点是像素缝中点（±0.5 px）再做高斯平滑。 |

### 1.1 这个问题固有的几何性质（调用方必须知道）

浪的网格是**开口薄片**。薄片从正侧面看过去，只有在表面**沿 Y 方向有变化**的地方才会填满轮廓：把截面沿 Y 纯粹拉伸得到的曲面，投影是一条面积为 0 的曲线，光栅化结果是空的。把隆起「封口」的是两端的收束：截面从完整形状缩到静水面的过程，扫过了浪体内部。由此有两种失败形态，库里都提供了检测手段，自测里都有示范图：

1. **没扫满 → 遮罩内部有未填充的洞。** `raster.hole_report(mask)`（以及 `extract_profile` 返回的 `profile['holes']`）报告洞的个数、面积、占比、包围盒。「洞」的定义：不与**画面上边**连通的背景区域（4 连通）。因为有水体，合法的背景一定连到上边；碰到左右边框的未填充区域同样算洞（合成浪的背在左边框处被裁掉，就是这种情况）。示范：`results/step1_prepare/measure/failure_no_taper_holes.png`（无收束的纯拉伸：`thin='skip'` 时网格像素数为 0；`thin='line'` 时只有一条线，洞占填充后轮廓面积的 46.0％）。
2. **两端较小的截面挡住空洞 → 内側の弧消失。** 如果收束方式只是把 Z 压扁（`taper='zscale'`），端部被压扁的波頭正好落在主截面的空洞里，从 `CAM_print` 看过去空洞被挡住，遮罩在那里是实心的。这是三维形态的性质（说明书 §5 注 2），不是测量的问题。示范：`failure_zscale_taper.png`、`failure_zscale_taper_crop.png`——真实空洞里有 568,193 px 被挡住，测得的轮廓变成一道竖直的崖：`overhanging = False`、θ = 90°、o = 0，S2／S7 必然失败。

合成浪默认用的收束（`taper='clip'`）是一种**保证不挡空洞**的构造：第 1 段把 X 截到 `min(X, c)`，c 从最右端移到内側の弧最深点的 X（波頭水平缩回浪体内部）；第 2 段再把 Z 乘以 g → 0。它只是测试夹具的做法，不是对 §7a 的方案建议。

### 1.2 与 Cycles 的交叉核对

`silhouette.render_mask_cycles()`：Cycles CPU、1 采样、白色自发光覆盖材质、黑色世界、Standard、dither 0、Blackman-Harris 像素滤波宽 0.01（采样点落在像素中心），水体用一块放在远处的发光平面。实测（合成浪终幕，3859×2594）：10,010,246 px 中 **4 px** 不一致（都是 numpy 遮罩有、Cycles 没有），全部在边界那一圈像素上；渲染约 1.1–1.3 s。图：`cycles_vs_numpy.png`。

`silhouette.setup_cam_print(scene, H)` 创建真正的 Blender 相机 `CAM_print`（调用 `gw.frame.Frame.make_cam_print`，全工程只有这一个实现），并用 `world_to_camera_view` 核对：与像素网格的最大偏差 0.0016 px。

## 2. 轮廓线提取（`extract_profile`）

1. 前景取**最大的 8 连通分量**；背景按 4 连通。其余分量不进入轮廓线，但**逐个报告**（加固）在 `profile['components']` 里：
   - `removed_area_px`、`n_removed`：被去掉的分量的总面积和个数；
   - `removed`：最大的 20 个，从大到小，每个给 `area_px`、`kind`（`speck`｜`island`）、`bbox_px` = [x0, y0, x1, y1)（遮罩像素，右下不含）、`bbox_H` = [X_min, Z_min, X_max, Z_max]、`centre_H`；
   - `n_removed_specks`／`removed_specks_area_px`、`n_removed_islands`／`removed_islands_area_px`；`speck_max_area_px`（本分辨率下的界限）、`speck_area_px_full_res`。
   - **碎屑（speck）与孤岛（island）的界限**：面积 < `silhouette.SPECK_AREA_PX_FULL_RES` = **25 px（全分辨率 3859×2594 下；= 5×5 px = 0.19％×0.19％ 画面高 = 8.5e-6 H²）** 的算光栅化碎屑，其余算真实的、脱离主体的几何（第二个对象、飞沫、从相机看过去悬空的一块网格）。界限按分辨率的平方缩放（半分辨率 6.25 px，1/4 分辨率 1.56 px；用矩形的「每 H 多少像素」对全分辨率的比值），同一块几何在各分辨率下分类相同。25 px 是我定的默认值（**解释・待确认**），不是说明书里的数。
   - **实测：空洞里放一块 0.07 H × 0.10 H 的脱离四边形（20,349 px），轮廓线和全部指标逐位不变**——孤岛只能从 `n_removed_islands` 看到，要不要因此判运行无效由测试层决定。
2. 不与画面上边连通的背景区域（洞）被填上，并记入 `profile['holes']`——调用方应当把「洞面积 > 0」当作遮罩不可信的信号。
3. 从**左边框**上、第 0 列最靠上的浪像素的上缘出发，沿像素缝前进，浪始终在行进方向右手侧，直到再次碰到边框。终点在右边框时 `complete = True`；波頂顶出画面上边等情况 `complete = False`、`end_border` 说明停在哪条边。
4. 顺序固定为：左边框 → 背 → 波頂 → 波頭 → 波頭の先 → 波腹（波頭下面）→ 内側の弧 → 谷 → 沿水面到右边框。空洞向右敞开，所以「内側の弧」= 波頭下方透出背景的那片区域的左边界（说明书 §5 注 2），不需要特殊处理；没有张出的早期帧（普通的涌）同样适用。
5. 输出：遮罩像素坐标 `px`、世界坐标 `world`、归一化坐标 `H`，`CAM_print` 矩形还给出原画像素坐标 `painting_px`；按弧长等距重采样（`exact` 时 1 px，否则 2 px）。

已知限制：如果取景太小，让波頭伸出右边框，波頭下方的空洞就只连到右边框而不连上边，会被当成洞填掉——取景要给波頭留出余量。

### 3.2 S8 轮廓的平滑

- 沿弧长每隔 `S8_sample_spacing_pct`（1％，取自 `params.json`）取一个采样点；「切线方向」= 相邻两个采样点之间的弦的方向；「相邻采样点的切线方向差」= 相邻两条弦的方向差，记在中间那个采样点上。为了不让折角躲在两个采样点之间，用 4 个相位（起点错开 1/4 间距）各算一遍，取最大。
- 评价范围：`[左端, 波頭の先]`（连续跨过波頂——S4 要求「顶部是圆的、没有折角」）和 `[波頭の先, 谷端]`；弦不跨过波頭の先，也不跨到沿水面的那一段。
- **波頭の先按段的边界处理（解释・待确认）。** 縁厚 ≤ 3％ H 的波頭，縁的圆头半径 ≤ 1.5％ H ≈ 1％ 画面高，切线在约 3％ 画面高的弧长内转过 ~180°，也就是每 1％ 间距转 ~58°，不可能满足 15°。所以距波頭の先弧长 `s8_tip_exclusion_pct_h` = 2％ 以内的采样点不参与判定；跨过波頭の先的总转角单独报告为 `tip_turn_deg`；同时报告不排除时的最大值 `max_unexcluded_deg`，供用户判断这个解释是否可接受。
- 输出：`max_tangent_diff_deg`（判定值）及其位置、分段最大值 `per_segment`。
- **判定值的三个盲点，以及与之并排的只报告量（加固；判定定义没有改）：**
  1. **弦会稀释折角。** 折角正好落在两个相位的采样点中间（离最近的采样点 1/8 间距）时，读数 = 折角 × 0.875：17° 的折角读 14.9°，通过。→ `max_vertex_window_turn_deg`：**折线自身**的转角——把折线自己各顶点的外角（带符号）在一个长 1 个 S8 间距（1％）的闭弧长窗口里求和，不用弦、没有相位；窗口在每个顶点处各放两个（以它为起点、以它为终点），滑动窗口的转角只在这些位置变化，所以取到的就是全部位置上的最大值；超过 180° 不回绕。这个标量**什么都不排除**（含波頭の先）。
  2. **折角逆着局部曲率时被抵消。** 8°／1％ 的弯上逆向折 20°，1％ 的弦和 1％ 的窗口都只读 12°。→ `vertex_window_turn['short_windows']`：同样的量在更短的窗口（`s8_vertex_short_windows_pct_h` = 0.5％、0.25％）上再算一遍。光滑曲线的转角随窗口缩短而变小（8°→4°→2°），折角不变（12°→16°→18°）。
  3. **波頭の先两侧 ±2％ 不判，而且以前连「不排除的最大值」里也没有任何一个跨过先端的采样点**（两段分开采样）：先端上一个 40° 的尖角，判定值 8°、旧的 `max_unexcluded_deg` 也是 8°。→ 现在 `max_unexcluded_deg` 里多了**一个正好放在先端上的采样点**（弦「先端−1％ → 先端」对弦「先端 → 先端+1％」，单独给出为 `tip_junction_deg`，带符号）；旧值保留在 `max_unexcluded_without_tip_junction_deg`。薄縁的波頭这个数本来就大（合成浪 66.8°），大形钝头约 10°。
  - `vertex_window_turn` 的其它键：`per_segment`（窗口中心在先端排除区之外，按中心归段）、`max_outside_tip_exclusion_deg`（与判定值可比的那个数）、`tip_zone_deg`（中心在排除区之内）、`across_tip_deg`（包含先端的窗口）、`max_at`、`n_windows`。
  - **性质（实测，读数时要知道）**：(a) 闭窗口最多容纳 ⌊w/d⌋+1 个顶点（d = 顶点间距），均匀弯曲的折线读 κ·(w+d) 而不是 κ·w——443 点的扫掠截面（d = 0.8％）上干净的轮廓读 16.5°，判定值 11.3°；1 px 间距的轮廓上这个偏差 < 4％。(b) 它对目标自己也成立：正式基準輪郭的背在 (929, 383) px 附近有一处 0.25％ 弧长内转 −19.9° 的小 S 弯，`max_vertex_window_turn_deg` = 19.1°，而判定值 10.3°。所以这组数**只能报告**；要不要设阈值、设多少，待用户决定。

### 3.3 S7 轮廓的一致（`s7_deviation`）

- 模型轮廓按 0.25％ 画面高的间距取点（比 S8 的间距密），量它到**基準輪郭同名段**折线的距离；反方向（基準輪郭的点到模型同名段）也量。每个方向给出 mean／p95／max（％ 画面高）。判定值 `mean_dev_pct_h`、`p95_dev_pct_h` 取两个方向中**较差**的一个。
- 同名段在比较时向两侧邻段各延伸 3％ 画面高的弧长（`s7_segment_margin_pct_h`）：模型和基準輪郭的波頂／波頭の先分界点不会完全一样，不延伸的话分界附近的点会被量到段的端点上，产生假的偏差。延伸有限，所以波頭上表面的点不会被匹配到下表面去。
- `in_S7 = false` 的基準輪郭点（被手前の浪或船挡住、补全的区间）：反方向不计入；正方向上，最近点落在这种区间上的模型点也不计入（数目记在 `n_skipped_not_in_S7`）。
- 以上几条是实现 §5 S7 时的选择（**解释・待确认**）。
- **带符号的法向偏差（加固，只报告）。** 同样的采样点、同样的最近点，另外给出偏差的**符号**：**正 = 模型轮廓在目标浪体之外**（在空气里或空洞里，即模型在那里更「胖」），负 = 在目标浪体之内（更「瘦」）。依据：本工程所有有序轮廓都是「浪体在行进方向右手侧」（左边框 → 波頂 → 先端 → 波腹 → 内側の弧 → 谷），所以点在目标折线行进方向的**左侧**就是在浪体之外；符号 = cross(切线, 点 − 最近点) 的符号，最近点落在折线顶点上时切线取相邻两条边单位切线的平均（`pm.signed_point_polyline_distance`）。反方向（目标点 → 模型折线）的符号取反，使两个方向的含义一致。每段给 `signed_mean_dev_pct_h`（= 模型→目标方向的带符号平均；该方向没有可计的点时用反方向），两个方向的字典里各有 `signed_mean_pct_h`、`signed_median_pct_h`、`signed_p05_pct_h`、`signed_p95_pct_h`、`frac_model_outside`。
  - 为什么要它：「放宽 5％ 同时压低 1.9％」时，背被同时向外、向下推，两个缺陷在无符号的 S7 里**部分抵消**（正式轮廓上背 mean 0.80％ < 1％，通过）。带符号的数显示方向：背 −0.51％（p05 −1.85、p95 +0.60：下半段在外、上半段在内）、波頭 −0.63％、内側の弧 +0.63％。单独的带符号平均值同样可能接近 0（自测里的折线：背 −0.04％ 而无符号 0.71％），所以要和 p05／p95、§3.9 的形状描述量一起看。
  - 符号约定用一个与库无关的方法核对过（自测）：把目标浪体当作闭多边形，对每个模型采样点做点在多边形内的判断，9 组（3 段 × 3 种变形）的带符号平均与库的差 ≤ 4.5e-5％。

| 高度 | `width_levels_H` = Z = 0.25、0.50、0.75 H（**绝对高度**，即原画上同一行像素；目标和模型在同一行上量。不是各自 h 的百分比）。标签 `z25`／`z50`／`z75`。 |
| `x_back_H` | 背（起点→波頂）与该水平线的交点中最靠左的一个。背在这个高度已经出了画面左边（起点的 Z ≥ 该高度）时，取轮廓的左端（= 画面左边框），并标记 `back_clipped_at_frame_edge = true`——这时「宽度」是从左边框量起的。**实测：`target/base_contour.json` 的背在 Z = 0.509 H 处碰到左边框，所以 z25、z50 两个高度的背都在画面外，只有 z75 是真正的「背到前面」的宽度。** 这是原画构图决定的，不是测量的问题。 |
| `x_front_H` | 前面（波頂→谷端）与该水平线的交点中最靠右的一个 = 该高度上浪体最靠前的点。 |
| `x_inner_H`、`overhung` | 前面与该水平线有 ≥3 个交点时，这个截面是「悬空」的（浪体–空洞–波頭）：`x_inner_H` = 最靠左的交点 = 主浪体在这个高度的右端（通常就在内側の弧上，`inner_on_segment = inner_arc`；如果是波頭上表面的凹兜造成的，会标成 `head`）。`cavity_gap_H` = 它右边第一个交点 − `x_inner_H`（该高度上空洞的宽度）。 |
| `width_full_H`、`width_body_H` | `x_front − x_back`；`x_inner − x_back`（只在悬空的截面上有）。 |
| `front_from_crest_H`、`inner_from_crest_H`、`back_from_crest_H` | 以上各点到**波頂铅垂线**（该轮廓自己的 x_c）的水平距离；背被画面裁掉时 `back_from_crest_H` 不给。以波頂铅垂线为轴放宽 k 倍时，这几个量恰好变成 k 倍，所以即使背在画面外，它们也能直接显示「宽了多少」。 |
| `o_H`、`cavity_depth_H` | 同 §3 的 o 与 `cavity_depth`（放在一起方便对照）。 |
| `area_above_still_water_H2` | 轮廓（左端 → 谷端）、左端的铅垂线、Z = 静水面 三者围成的面积（H²；鞋带公式，波頭下面的空洞不算在内）。注意左边被画面裁掉，所以放宽 k 倍时面积的增幅小于 (k−1)。 |
| 比较 | `compare_width_metrics`：每个量给出 模型、目标、差、**差占目标的 ％**、差折合画面高的 ％（长度量）；两边截面种类不同（一边被裁／一边悬空）时标 `comparable = false`。 |

自测：直线拼成的「下垂波頭」折线上各交点与闭式解的差 ≤ 1.1e-16 H；面积与独立的像素计数（1000 px/H）相差 < 0.2％（0.77999 对 0.77995 H²）；三角波的面积、z75 宽度与闭式解一致到 1e-6；放宽 5％ 的副本读数 +5.000％。自检（`selfcheck_tests.py`）里放宽 5％／8％／10％ 的合成浪，经过网格和遮罩之后的读数是 +5.00／+8.00／+10.00％（z75 宽度、到波頂铅垂线的距离、o、空洞深度），面积 +2.54／+4.01／+4.98％；同时 spec 档只在 8％ 时报一项（背 mean 1.19％）。

### 3.8 最大回撤规则的已知边界

- 如果前面区间里有两个彼此分开的悬空（例如上方一瓣很大的凹兜，加上下方真正的空洞），规则选回退量大的那一个；两者大小交替时，先端会在帧与帧之间跳。合成浪和 Houdini 参考的 110 条轮廓上没有出现。
- 波頭如果在到达最深点之前就碰到静水面，前面区间在那里结束；但那时遮罩里的空洞已经闭合成「洞」，`extract_profile` 会报告洞，有效性不通过。

### 3.9 不会相互抵消的形状描述量 `shape`（加固；**只报告，没有阈值、这里不下结论**）

问题：W（§3.7）在**绝对高度**上切截面。模型「宽 5％ 同时矮 1.9％」时，Z = 0.75 H 这一行切到的是浪体更靠上的位置，z75 宽度读 **−5.22％**（审查实测），而形状其实是相对高度宽了 8％——这正是用户当初的意见「太宽、不够高」。

定义（`measure_profile(...)['shape']`，`pm.shape_descriptors()`，`pm.compare_shape_descriptors(model_shape, target_shape)`）：

| 量 | 定义 |
|---|---|
| 截面高度 | 每条轮廓在**它自己的**波頂高度 h 的 0.25／0.5／0.75 处切（`shape_levels_frac_h`；Z = 静水面 + f·h），标签 `h25`／`h50`／`h75`。模型用模型的 h，目标用目标的 h。 |
| `sections[tag]` | 与 W 的截面记录相同的字段（`x_back_H`、`x_inner_H`、`x_front_H`、`overhung`、`back_clipped_at_frame_edge` …），外加 `frac_of_h` 和每个长度除以 h 的版本：`width_full_over_h`、`width_body_over_h`、`front_from_crest_over_h`、`inner_from_crest_over_h`、`back_from_crest_over_h`、`cavity_gap_over_h`。 |
| `o_over_h`、`cavity_depth_over_h` | o ÷ h、空洞水平深度 ÷ h。 |
| `aspect_ratio`、`aspect_ratio_back_clipped` | 纵横比 = 0.5 h 处的 `width_full` ÷ h。**实测：正式基準輪郭的背在 Z = 0.509 H 碰到画面左边框，所以 0.5 h 处的宽度是从左边框量的（`aspect_ratio_back_clipped = true`），它不随浪体缩放**；因此同时给 `aspect_ratio_h75`（0.75 h 处，背还在画面内）和 `aspect_ratio_h75_back_clipped`。 |
| 比较 | `compare_shape_descriptors`：每个量给 模型、目标、差、差占目标的 ％；`comparable = false` 的情形：两边截面种类不同，或背被画面裁掉而这个量又是从背量起的（`width_*`、`back_from_crest`、对应的纵横比）。 |

性质：纯粹「宽 k 倍、矮 m 倍」是仿射变换，相对高度切到的是同一批物质点，所以**每一项都读 k/m − 1**。实测（宽 1.05、矮 1.9％ → 期望 +8.11％）：自测折线 11 项与期望差 ≤ 0.007 个百分点；合成浪经网格和遮罩 9 项 ≤ 0.009；正式轮廓扫掠（审查的 `wide_low:5:1.9`）o/h +8.33、空洞深/h +8.07、`aspect_ratio_h75` +8.09、h75 后距/h +7.90（不加缺陷时这几项本来就是 +0.19／−0.04／−0.02／−0.19），而 `aspect_ratio`（被裁）只读 +3.28。

### 3.10 测量参数的读取规则与 `non_default_params`（加固）

- `pm.get_params()` 只捕获**「这一项不存在」**（`KeyError`）：`params.json` 里没有 `S8_sample_spacing_pct` → 用 `S8_SPACING_DEFAULT_PCT_H` = 1.0；没有 `measure_params` → 全部用默认值。其它情况一律**抛异常**：`params.json` 缺失或 json 写坏（以前会被整个吞掉、悄悄用默认值量）、`measure_params` 不是对象（`TypeError`）、参数名不认识（`ValueError`，防止拼写错误悄悄失效；`comment`／`provenance`／`unit` 这几个说明键允许出现）、间距不是数（`ValueError`）。`_frame_h()` 的「读不到就用 100/66」的回退也去掉了。
- 返回的扁平字典里多一项 **`non_default_params`** = {参数名: {`value`, `default`, `source`}}，列出每一个与 `DEFAULT_PARAMS` 不同的测量参数（S8 间距与 1.0 比）；`source` = `params.json` 或 `override`（调用时传入的）。空字典 = 全部按本文件写的默认值量。`measure_profile(...)['non_default_params']` 是同一个东西，`pm.non_default_params()` 直接返回它。把 `get_params()` 的结果原样再传回去当覆盖值是允许的。
- 本工程目前 `non_default_params == {}`（自测里有一项检查）。测试层应当在它非空时把它显眼地标出来。

### 3.11 已知限制（加固时实测到的，不是缺陷修复）

- 被去掉的孤岛如果在投影里与主体**重叠或相连**，就不再是独立分量，这里看不到（例如贴着浪体的第二个对象）；抬高的海面就是这种情况，它靠 `trough_level_H` 发现。
- `trough_level_H` 取的是最深点之后的**最低点**。如果浪前面的海面只在远处落回 Z = 0（近处抬高），它读 0、`reached_still_water = True`；这种形状会在 S7 内側の弧（没被遮挡的部分）和沿水面那一段上表现出来，但目前没有专门的量。
- `max_vertex_window_turn_deg` 对顶点间距敏感（§3.2 性质 (a)），并且目标自己就读 19.1°（性质 (b)）。

## 4. 需要用户确认的解释（汇总）

1. 波頂的横向位置用「稳健极值」（tol = 0.1％ 画面高），而不是单纯的最高像素。
2. 波頭の先 =「波頂 → 第一次碰到静水面」这一段里水平回退量最大的一对点（先端 T、最深点 D）中的 T，也就是整个悬空波頭上最靠右的点（2026-09-20 修订，§3.6）；最大回退量 ≤ 0.3％ 画面高视为没有张出（这一条与旧规则相同）。
3. o 在张出刚出现时不连续（定义本身的性质）；是否并用 `cavity_depth`。
4. θ 的窗口（2％ 画面高的弦）、顺时针 0–180° 刻度、把波頭下表面算进「前面」。
5. φ 取上表面距先端 2％–8％ H 弧长一段的弦方向。
6. S4 三处的窗口位置和三个布尔判断的容差。
7. S8：弦定义的切线、4 个相位、波頭の先前后 2％ 画面高不参与判定、先端转角单独报告、评价连续跨过波頂、不含谷端的折角。
8. S7：分段比较 + 3％ 延伸、双向取较差者、0.25％ 采样、`in_S7` 的处理方式。
9. S6 的「浪体最右点」不含浪脚。
10. 水体填到 Z = 0：低于静水面的谷在轮廓里不可见。
11. 「洞」= 不与画面上边连通的背景。

2026-09-20（库修订）新增：

12. S5（和 M4）的朝向**就是 φ**，模型和基準輪郭用同一个函数；「波頂→先端」的方向只并排报告（§3.4）。
13. 基準輪郭的 json 接缝与库的检测相差 > 0.2％ 画面高时，`test_shape` 判 INVALID 而不是 FAIL（0.2％ 是 orchestrator 给的值，§3.6）。三个点（波頂、先端、最深点）都算；目前指状尺度的 `target/base_contour.json` 因为**波頂**差 0.240％ 而不一致。
14. 只报告的尺寸指标 W（§3.7）：高度取绝对的 0.25／0.5／0.75 H；背出画面时从左边框量并标记；悬空截面的判定（≥3 个交点）；面积的定义。**这组数没有阈值，要不要设、设多少，待用户决定。**

2026-09-20（加固）新增：

15. 碎屑与孤岛的界限 = 全分辨率 25 px，按分辨率平方缩放（§2）。孤岛是否让运行无效，由测试层／用户定。
16. 模型自己的谷水位 = 最深点到右边框之间的最低点；「到达静水面」的容差 = 0.3％ 画面高（与谷端相同）；`S3_from_model_trough` 是否参与判定（§3.4）。
17. 形状描述量 `shape`（§3.9）：相对高度 0.25／0.5／0.75 h、全部除以各自的 h、纵横比取 0.5 h（目标在这一高度被画面裁掉，另给 0.75 h）。**没有阈值。**

20. 测量参数名不认识、`params.json` 写坏时一律报错而不是用默认值（§3.10）。
