# 局所的な高峰と分岐白波の改訂試作

## この段階の判定

**制作目標は未達であり、完成版とは扱わない。** 旧版の梁状の波頭を見直した比較用の途中成果である。

[斜め視点の動画](../../deliverables/localized_wave_volume.mp4)と[原画方向の動画](../../deliverables/localized_wave_print.mp4)は各30 fps、345フレーム、11.5秒。第285フレームで形状を固定し、最後の2秒間を比較用に静止させている。参考展示の連続的な波の通過を再現したものではない。

## 旧版で確認した問題

実際のレンダリングで、波頭が直線の梁、浪体が板、白波が細いひげに見えた。中央断面と一台のカメラの輪郭検証だけでは、この立体的な問題を判定できなかった。旧版の数値テストの合格を、新しい立体の品質評価へ流用しない。

## 今回変えた内容

1. `localized_sweep.py`：峰方向の等高区間をなくし、近側と遠側で幅、高さ、後退量を変えた。低い肩は発達段階を変え、高い肩は巻込みを保つ。中央断面への頂点の押込みは行わない。
2. `branching_whitewater.py`：細い管から、連続した根元と回鉤を持つ厚片へ変更した。白波を高い部分に集め、峰方向と断面方向に配置した。
3. `build_localized_scene.py`：主波、白波、小滴、周辺海面を別のメッシュとして生成した。主波と周辺海面の低い縁には同じ世界座標の模様を使い、四角い制作領域の境界を弱めた。
4. 絶対シェイプキーにアニメーションを格納した。主波と分岐白波は4フレーム間隔の72姿勢を線形補間する。小滴は2フレーム間隔、周辺海面は8フレーム間隔である。

## Blender MCP の実行経路

今回の新規シーン生成とレンダリングは、公式 [MCP for Blender](https://github.com/ahujasid/mcp-for-blender) の stdio MCP サーバーから `execute_blender_code` を呼び、公式アドオンを経由して実行した。`initialize`、`list_tools`、`get_scene_info` の成功も確認した。

- 配布パッケージ：`mcp-for-blender 2.0.3`、`mcp 1.30.0`
- 参照した公開ソース：`7cc602252386b92829bc7364e3a897253610be38`
- アドオンの通信規約：9
- Blender：5.2.2 LTS
- 接続：同じPCの `127.0.0.1:9876`

既存の未保存シーンを別名のローカル副本に保存した後、独立した Blender インスタンスで作業した。以前のバックグラウンド生成を、MCPで実行済みだったとは記録しない。

## 参考として確認したもの

- 原画：`reference/Tsunami_by_hokusai_clean.jpg`
- 利用者の静的3Dモデル：`wave_repair_zbrush2.obj`。開口と立体の収束を参照し、メッシュを完成品へ複製していない。
- 利用者のローカル展示記録：`HOKUSAI ANOTHER STORY in TOKYO` の約54～60秒。高い水体、広い白波、分岐した回鉤、独立する水滴を観察した。録画素材自体は転載していない。
- [制作会社による紹介](https://www.inbetween.jp/jp/work/hokusai)と[制作担当者のメイキング](https://note.com/taishiyagyu/n/nd1d49b73e11a)。演出的な手付けも含むため、展示の外観を流体物理の正解とは扱わない。

## 確認結果

独立した Blender プロセスで保存済みファイルを読み直した。30 fps、1～345フレームで、外部キャッシュ、画像参照、外部ライブラリーはなかった。

| メッシュ | 頂点 | シェイプキー |
| --- | ---: | ---: |
| 主波 | 50,941 | 72 |
| 周辺海面 | 25,921 | 37 |
| 小滴 | 1,080 | 143 |
| 分岐白波 | 24,528 | 72 |

主波・周辺海面・白波の第1、152、285フレームはそれぞれ異なった。小滴は185フレーム以後の放出のため、第1と152フレームは同じだった。4つのメッシュとも第285と345フレームの評価済み頂点は完全に一致した。

両動画を全フレーム復号し、H.264、960×600、30 fps、345フレーム、11.5秒であることと、時刻情報が単調増加することを確認した。抽出した8姿勢の画像も確認した。斜め視点の第314と344フレームは画素単位では同一ではなく、平均チャンネル差は255段階中0.999だった。幾何形状の一致と動画の画素の一致は区別する。

改訂した掃引の6つの主要姿勢で、121本の各XZ断面に厳密な線分交差がないことを確認した。これはすべての非隣接三角形の三次元衝突を証明したものではない。原画方向、斜め、船上に相当する視点の画像を別に確認した。

## 残る問題

- 白い波冠が広く均一で、原画の細かい枝分かれと色面の関係は未再現。
- 白波はまだ巻いた葉や花弁に見える。船上からは厚片の重なりが目立つ。
- 船上視点では主波が細い壁に見え、参照モデルのふくらみと倒れ込む下面を十分には表現できていない。
- 周辺海面の模様が規則的で、複数の波の重なりと飛沫の規模が不足する。
- 形成後に静止する。波の継続的な進行・崩落・次の波への接続は未実装。
- 主波は美術的に制御した変形であり、体積保存や流体方程式を検証していない。小滴に重力を用いても、全体が流体シミュレーションになるわけではない。
- Unityへの変形データ転送、材質の移植、船の操作、HMDでの性能は別段階で未検証。

## 再生成

Blender の Python から `src` をモジュール探索先へ加えて実行する。

```python
from gwave.build_localized_scene import build, render_movie
build(step=4, foam=True)
render_movie('CAM_立体確認', suffix='volume')
render_movie('CAM_原画方向', suffix='print')
```

出力は `results/localized_rebuild/`。確認後の比較用ファイルだけを `deliverables/` へ移す。MCPを使用する場合も、同じ関数を公式のコード実行ツールから呼び出す。
