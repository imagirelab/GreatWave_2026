## 初期に判明した問題

当初、指状尺度の target/base_contour.json をそのまま網目化しても spec 段階の形状検査で9項目が失敗した。旧先端検出は複数の泡の小片の上側を拾い、JSONの先端接合点と画面高の15.9％ずれた。そのため同じ輪郭を比べても S5 と S7 が失敗した。さらに目標輪郭自身の S8 は背23°、波頭86°、内側の弧67°で、15°上限を満たさなかった。これは網目だけの数値誤差ではなく、目標と定義の矛盾だった。

旧規則は後に「最大戻り」に改められ、先端接合点のずれは0.008％になった。指状尺度の細部をそのまま静止形状の目標とする問題は、半径150 pxの大形目標を別に作ることで整理した。したがって、ここにある9項目失敗を現行の輪郭へそのまま当てはめない。

形状の「太すぎる」問題には試験が鈍感だった。波頂の鉛直線を中心に横幅を5％広げても spec 段階では失敗項目が0件、8％で初めて背の平均偏差が1.19％となった。単純な位置・最近接距離だけでは幅と高さの複合誤差が相殺される可能性がある。後に W と shape の報告専用量を追加したが、その閾値は未設定だった。

初期の故障注入では、自己交差を意図した形が最初は実際に自己交差しておらず、純粋な引き延ばしは本来の有効性失敗を起こさなかった。波頂+3％の入力が画面から2.43％と読まれ、直接輪郭と網目経由の予測が一致するだけでは測定の絶対精度を保証できないと分かった。M2／M4の単調性は、解析上は完全でも高さ5.6e-6 H、角度0.012°の測定雑音で失敗し得るため、後の実装で原値を保存しつつ雑音下限を導入した。M6の式も当時の解釈であり、バックログの中央値式と一致していなかった。

当時の自己検証は最終的に15組が期待に一致したという記録である。後続の更新で17組、さらに38組へ増えた。試験結果の元データは results/20260920_065550_selfcheck/ と各結果フォルダにあり、再実行は tools/run_blender.ps1 に tests/selfcheck_tests.py を渡す。初期実装が作品全体の合格を示すものではない。
