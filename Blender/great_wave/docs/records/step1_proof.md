## 2. 实测到的事实

### 2.1 收束方式（`taper`）：`clip` 为什么不行，`lift_clip` 怎样保证不进空洞

- `clip` 的做法是 X′ = min(X, c)：把波頭的点**水平**向左移。原画的空洞顶部在腋部最高 (1701, 907) px，波頭下面向右下降到 (2036, 995) px，所以下面的点水平左移时正好穿过空洞 → 并集轮廓的空洞顶部变成 y = 995 的一条水平线（之前两次扫掠测试里 S7 内側の弧 p95 3.16 ％、S8 65° 的来源）。
- `lift_clip`（新增，定义写在夹具的模块说明里）：每个顶点的路径都是**中央截面内部的直线段**。
  - 第 0 段（收束坐标 d 1 → 0.8）：「波頭の先 → 最深点」这一段**竖直向上**（向波頭内部）抬到「从最深点数过来的 Z 的累计最大值」。抬完以后，下面任何一点都不低于它左边的空洞顶部。
  - 第 1 段（d 0.8 → 0.5）：同 `clip` 的水平截断；另外，被截到 x = c 的点不得高于中央截面在 x = c 处的上边界（防止波頂在截断线右侧时被整高度向左抹开——`step1_tests.md` 3.3 里「+3 ％ 读成 2.43 ％」的原因）。
  - 第 2 段（d 0.5 → 0）：Z′ = g·Z，同 `clip`。
  - 网格、顶点数、Y 方向的布局与 `clip` 完全相同；`clip`、`zscale`、`none` 的代码一行没改。
- 证明（`taper/taper_proof*.json`；遮罩 3859 × 2594，两边都用「像素中心」覆盖规则；顶点检验含每个站的全部顶点和到下一站连线上 λ = 0.25／0.5／0.75 的点，共 99,675 个）：

| 正式轮廓__clip | 608 | 3.324 | 21,267（87.0） | 0.832 | 0 | 0 |

- `lift_clip` 在解析合成浪上也试过（临时脚本，6 个帧）：多出 0、缺 0、洞 0，与 `clip` 相同。

## 4. 我的推测（不是实测）

- 第 2 步的真实模型只要截面不逐像素照抄手绘的背（比如用少量控制点的样条），`S4.flattens_towards_crest` 自然会过；正向对照说明这样做在 S7 上的代价约 0.1–0.4 ％。但如果模型「故意」贴得很紧（S7 背 < 0.05 ％），这一项反而会不过——这一点应当让做模型的人事先知道。
- φ 对钝头不敏感这一点，在动态测试 M4（「φ 单调向下」）里可能同样出现：卷入阶段波頭整体下转时，φ 的变化可能远小于实际转角，甚至被圆头形状的微小变化主导。没有在动态上实测。
- 放宽 8 ％ 时内側の弧 p95 只超限 0.007，模型离散或遮罩分辨率稍有不同就可能翻转；「8 ％ 报 5 项」不应当被当作稳定的灵敏度指标，稳定的只有 S5 位置（2.28）、背 mean（1.24）、背 p95（2.31）、波頭 p95（2.17）。
- `lift_clip` 只是夹具的收束，不是 §7a 的方案提议。但它暴露的几何事实对 §7a 有用：任何「把截面沿某个方向平移／截断」的收束，都必须先处理「波頭下面比腋部低」这件事，否则侧面看空洞会被挡住。

## 5. 建议

1. **`S4.flattens_towards_crest`**：请用户在两种处理里选一种——(a) 对基準輪郭自身只报告、对模型照常判定（模型必须比手绘的背更光顺，代价 ≤ 0.4 ％）；(b) 把判定改成对「斜率的平滑趋势」判定。阈值文件不归我改，我没有动。
